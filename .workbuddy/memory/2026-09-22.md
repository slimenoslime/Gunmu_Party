# 2026-09-22 · 滚木派对

## 修：安卓版一进比赛就崩 —— 类路径资源没打进 APK（D64 / a0.0.2）

用户报的堆栈（`SceneRenderer.render` → `ModelBatch.render` → `DefaultShader.getDefaultVertexShader`）：

```
GdxRuntimeException: File not found:
    com/badlogic/gdx/graphics/g3d/shaders/default.vertex.glsl (Classpath)
```

**根因**：打包只编了 `.class`。libGDX 的 `DefaultShader` 用 `Gdx.files.classpath(...)` 读
着色器源码，`BitmapFont` 读 `lsans-15.fnt/.png`。Gradle 打 APK 会把 jar 资源铺到根部
（`mergeJavaResource`），我们这条直连工具链的路没有这一步。
证据是**桌面 jar 里有这 6 个 `.glsl`（`build_jar.py` 整包合并）而 APK 里没有** ——
所以这个 bug 只在安卓爆，且只在进比赛那一帧爆（第一次 `ModelBatch.render`）。

**改法**：
1. `tools/build_apk.py` 新增 `classpath_resources()`：按**黑名单**把非 class 文件铺到 APK 根部
   （跳过 `.class` / `META-INF/**` / `.gwt.xml` / `.rl` / Kotlin 编译期元数据 / 无扩展名条目）。
   实测 26 个 jar 里真正要铺的只有 **8 个文件 / 49.3 KB**。
2. `tools/verify_dex.py` 增加**资源完整性**检查：从 dex 字符串表反查"按路径读文件"的路径，
   断言在 APK 根部或 `assets/` 下存在，否则中止构建。对修复前的包报 14 条（其中 8 条正是缺的资源）。

## 顺手排查的同类隐患（都没爆）

- `.so` 是**压缩**进包的 → 必须有 `android:extractNativeLibs="true"`（清单里原来没写，靠缺省）。
  已显式写上 + 新增 `check_native_packaging()` 断言（压缩 + 没写 true → 中止构建）。**D65**。
- 把 dex 里所有"含 `/` + 扩展名"的字符串按扩展名分组统计过一遍：只有 `.prof`/`.profm`
  （基线配置文件）与 `text/vnd.android.intent`（MIME）三类不在检查清单里，且都不是被读的文件 → 网没漏。
- `Fonts.CANDIDATES` 里那串 `/system/fonts/...` 是 `Gdx.files.absolute` 的设备路径 →
  资源检查里"以 `/` 开头即跳过"（否则 6 条系统字体误报）。Windows 盘符路径靠"含冒号"排除。
- 反编译确认 `AndroidGraphics.preserveEGLContextOnPause()` → `setPreserveEGLContextOnPause(true)`：
  切后台不丢 GL 上下文。`Screenshot` 靠系统属性开启，安卓上取不到即关闭；不需要任何权限。

## 版本策略

- 用户口述的 `a/b/v` 前缀规范已落地，但 a0.0.1 期间**同一版本号被打过三次不同的包**
  （首个构建 → 修闪退 → 修着色器），报 bug 时说不清装的是哪一个 →
  **本次升到 a0.0.2（code 2）**，并把"同一版本号不许有两份不同的包"写进 README 与 CHANGELOG。
- 固定签名不变（SHA-256 `9378eae8…c7f5`），所以覆盖安装即可，不用卸载。
