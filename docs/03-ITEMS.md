## 1. 道具的通用规则

| 项 | 值 |
|---|---|
| 携带上限 | **1 个**（每根滚木） |
| 拾取判定 | 中心距离 < 1.6 m 且 高度差 < 2.0 m |

| 背包已满踩到道具 | 道具不消失，玩家被弹开（不消耗） |

## 1.1 刷新池按模式过滤 🔒

**竞速图不刷"战斗专用"道具。**

竞速图里大家各跑各的，被打断也只是摔一跤然后接着跑，所以下面这些刷出来就是空道具：

| 类别 | 道具 | 为什么竞速里没用 |
|---|---|---|
| 纯防御 | 背手负鼠、外耗、酱板鸭反转、轻松绷住 | 没有需要防的攻击来源 |
| 纯输出 | 千薪万苦（血越少打得越狠） | 没有目标可以打 |
| 反隐 | 长沙挺热（看破隐身与伪装） | 看不到需要看破的人 |

共 **6 / 27** 个。竞速图的可刷池因此是 **21 个**。

实现上只改一处：`MapDef.weightOf()` 在 `mode == RACE` 时对 `ItemType.combatOnly()` 返回权重 0。
刷新点、稀有保底、以及**盲盒开出来的东西**全都走它 —— 盲盒是个后门，不堵住等于没修。

> 划分是**显式枚举**，不按稀有度或权重猜。漏一个就是一个坑，
> 所以 `tools/ItemPoolTest` 会逐张竞速图把刷新池刷上万次，断言
> 「出现过的道具集合 == 全集 − 战斗专用」**集合完全相等**（既不许多也不许少），
> 并反查生存/竞技图确实会刷出全部 6 个（防止做成"全局关闭"）。
>
> **§4.6 的 4 个竞速向速度道具都不算战斗专用**：抬上限、抬起步、瞬移、给自己铺加速带，
> 在任何模式下都成立（也是刻意这么设计的 —— 竞速图最缺的就是"跑得快"）。
>
> 另注：这 6 个**没有一个是普通品质** —— 否则竞速图的"连续 3 次普通 → 强制稀有以上"
> 这条保底会无解。

## 2. 刷新点机制

🔒 **刷新点位置是地图数据的一部分，永远固定。**

```
ItemSpawnPoint {
    Vec3 pos;              // 绝对不会变
    float respawnTime;     // 该点重刷时间，默认 12s（L5 决战关 = 9s）
    ItemState state;       // READY | EMPTY
    float respawnTimer;
    ItemType current;      // 当前刷出来的东西
}
```

流程：

```
关卡开始  → 所有刷新点 state = READY，各刷 1 个（按权重抽）
被拾取    → state = EMPTY，respawnTimer = respawnTime
计时归零  → 重新抽 1 个 → state = READY
```

**抽签规则**：按该玩家所在**地图的权重表**加权随机。全局默认权重列在 §4 的「权重」列；单张地图可覆盖（见 §5）。

**保底**：同一个刷新点连续 3 次抽出「普通」稀有度 → 第 4 次强制「稀有」及以上。

### 4.6 竞速向速度道具（跑得快）🔒

需求来自用户口述：「**给竞速图多加点实用的速度道具**」。

竞速图在按模式过滤掉 6 个战斗专用道具之后只剩 21 个可用，而其中真正**加速自己**的
只有 `chain_gears` / `zuowan_nide` / `xie_xiu` 三个 —— 四张竞速图轮着抽，很快就腻了。
下面四个都是"跑得快"的正统解法，且都**不限模式**（生存/竞技里一样有用）：

| # | id | 名称 | 出处（2026 热梗） | 效果 | 时长 | 权重 | 稀有度 |
|---|---|---|---|---|---|---|---|
| 24 | `yaoyao_lingxian` | 遥遥领先 | "断崖式领先"，发布会式夸口的通用化 | 移速 **+35%**，下坡速度上限 22 → **28 m/s** | 8 s | 8 | 稀有 |
| 25 | `zao_ba` | 早八 | "早八生死时速：八点的第一节课，七点五十九还在楼下" | **起步冲量**（速度立刻抬到 14 m/s）+ 加速度 **×1.5** | 6 s | 11 | 普通 |
| 26 | `shan_xian` | 闪现 | "MOBA 里的保命键，冷却一好手就痒" | 朝前方**瞬移最多 12 m**（落点必须在路面上）+ 0.6 s 无敌 | 瞬时 | 5 | 史诗 |
| 27 | `yi_lu_lu` | 一路绿灯 | "打工人通勤的最高礼遇：一路没红灯" | 在身前铺一条 **3.4 × 10 m 的加速带**，进入者被推着往前跑 | 8 s | 8 | 稀有 |

三个实现要点：

1. **`yaoyao_lingxian` 抬的是速度上限**（`Roll.maxSpeed()`），不是给一次冲量 ——
   与加速（`Shift`）同一条思路：要的是"这段时间里真的更快"，而不是弹一下。
2. **`zao_ba` 的起步冲量受本帧速度上限约束**：它只是把当前速度沿朝向抬到 14 m/s，
   接下来照常被 `PhysicsWorld` 的 cap 钳制，所以不会出现"平地冲出 20 m/s"。
   加速度倍率走 `Roll.accelMultiplier()`，作用点是物理里那两处 `MOVE_ACCEL`。
3. **`shan_xian` 必须逐 0.5 m 探路**（`ItemSystem.blink`）：直接 `pos += dir × 12` 的后果是
   竞速图两侧的虚空里多一具尸体 —— 遇到不可行走或落差超过 3 m 就停在上一个安全点；
   前方完全没路时原地不动（但无敌帧照给）。

**计数校验：6 + 7 + 4 + 5 + 3 + 2 = 27 ✓**

## 6. 结算顺序（同一帧内多个效果触发时的固定优先级）

```
1. 免疫检查        （无敌帧 / 正太扭腰 / 背手负鼠免死 / 酱板鸭反转）
2. 伤害修正        （破防 ×1.35 → 蛋挞 ×1.30 → 千薪万苦加成 → 电子布洛芬归零）
3. 伤害结算        （延迟结算队列 → 轻松绷住推入队列）
4. 反弹            （外耗 50% / 酱板鸭 100% → 递归深度上限 1，反弹不再被反弹）
5. 掉血 / 碎掉     （HP ≤ 0 → destroy）
6. 事件派发        （OnDamaged / OnKilled / OnDestroyed）
```

**反弹递归上限为 1**：外耗反弹造成的伤害不再触发对方的外耗，否则两人互撞会无限递归。这是硬性约束。

## 7. 与其他系统的交互

| 交互 | 规则 |
|---|---|
| 道具 vs 决战技 | 两者独立并存。同一实体可同时持有 1 个道具 + 1 个决战技。 |
| `changsha_hot` vs `忘情牛肉面`（隐身决战技） | `changsha_hot` 生效期间可看破隐身。 |
| `pigeon_pop`（输入反转）vs AI | AI 的输入同样被反转，AI 不做特殊补偿——它就真的会走歪。 |
| `money_free` vs `我的世界皓宸`（复制技能） | 复制来的技能同样会被丢弃（视作一个可丢弃的增益槽）。 |
| `blind_box` vs 自身 | 不递归。 |
