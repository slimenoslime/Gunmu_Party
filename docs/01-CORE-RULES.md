## 1. 时间轴（Tick）

| 项 | 值 | 说明 |
|---|---|---|
| 逻辑帧率 | **60 Hz 固定步长** | `dt = 1/60`，与渲染帧解耦 |
| 每渲染帧最多补算 | 5 个逻辑帧 | 防止卡顿后爆炸（spiral of death） |
| 关卡时限 | 见 `02` 各关 | 到时不立即结束，进入 10 s 结算缓冲 |
| 起点屏障 | 每个子图开局 **8 s** | 见 §1.1；这 8 s **不计入关卡时限** |

**为什么固定步长**：本游戏是可联机的派对竞技。可变步长会让同一份输入在不同机器上算出不同结果，之后做联机同步时无解。物理必须确定性（见 `05`）。

### 1.1 起点屏障（开局 8 秒）🔒

每个子图开始时，**所有人被一道圆柱屏障关在起点区域内 8 秒**。

| 项 | 规则 |
|---|---|
| 屏障形状 | 圆柱（无限高）：水平位置被夹在半径内，**跳起来也出不去** |
| 起点区域 | 中心 = 全部出生点的形心；半径 = 最远出生点到形心 + 3.5 m（下限 11 m） |
| 期间可否移动 | **可以**，完全自由。只抹掉朝外的速度分量（等价于贴墙滑），切向速度一点不减 |
| 8 秒后 | 屏障消失，**比赛时钟才从 0 开始**：关卡时限与生存关的涨水/毒圈都不在屏障期间推进 |
| 表现 | 半透明青色圆筒 + 地面基环；HUD 顶部中间给倒计时「起点封闭 x.xs」 |

**为什么"不限高"**：只要允许按高度判定，就会出现"起跳 + 被弹飞"越狱。
屏障是一道规则边界，不是一堵物理墙，所有高度上一视同仁最不容易出错。

**为什么比赛时钟要等屏障消失才走**：否则等于每个子图白扣 8 秒。
折返图本来就跑不满全程（见 `05` §10.5 的实测），再扣 8 秒就是雪上加霜。

**起点区域是从出生点推导出来的，不是手写坐标** —— 三种模式的出生点布局完全不同
（竞速是 6 列 × 5 排方阵、生存/竞技是环形），手写必然漂移。
推导结果由 `MapValidator.validateStartZone` 硬校验（出生点全在内、中心脚下可行走、半径不低于下限）。

## 2. 滚木的运动模型

### 2.1 形态

滚木是**圆柱体**，不是球。这是玩法核心：圆柱只能绕自身长轴滚，长轴朝向由玩家操控决定。

```
半径 r = 0.5 m
长度 L = 1.6 m
质量 m = 1.0（标准化，伤害用速度算不用质量）
```

🧭 仿真上用「等效球体做碰撞 + 独立维护长轴朝向做视觉滚动」的混合方案。理由：真正的圆柱-圆柱接触求解需要完整 GJK/EPA，成本高且难以确定性；而本游戏要的"滚木"感主要来自**视觉滚动 + 长轴方向影响滚速**，用等效球不会损失可玩性。

### 2.2 摇杆输入 → 移动方向

```
输入 = 摇杆向量 (ix, iy)，模长裁剪到 0..1
目标方向 D = 相机右向量 * ix + 相机前向量 * iy   // 世界空间 XZ 平面
```

- 摇杆是**全向**的，不是"左右转向 + 自动前进"。用户口述"用轮盘移动"即自由方向。
- **长轴对齐**：静止时滚木自动把长轴旋转到**垂直于**当前移动方向（横向滚），因为横向滚才滚得动；长轴平行于前进方向时会被明显减速。
  - 实际实现为一个 `alignFactor = |dot(longAxis, moveDir)|`，取值范围 [0,1]。
  - 速度乘子 `1.0 - 0.45 * alignFactor`（完全平行时只剩 55% 速度）。

### 2.3 受力

每逻辑帧：

```
1. 重力沿地形梯度：a_slope = g * (-∇h) / sqrt(1 + |∇h|²)
2. 输入推力：        a_in  = D * accel * inputStrength
3. 摩擦：            a_fric = -v_horizontal * friction(terrainType)
4. 空气阻力：        a_air = -v * 0.02 * |v|
```

| 地形 | friction | 说明 |
|---|---|---|
| 草地（默认） | 1.00 | |
| 岩面 ROCK | 1.20 | |
| 沙地 SAND | 1.80 | |
| 泥坑 MUD | 3.00 | 极黏，下坡也快不起来 |
| 冰面 ICE | 0.35 | 打滑、转向变钝，但还能控住方向 |
| 加速带 BOOST | -3.0（负摩擦 = 加速） | 定向推力 14 m/s² |
| 传送带 conveyor | — | 附加 6 m/s 的切向速度 |
| 弹跳台 BOUNCER | — | 进入时给 vy = 11 |

### 2.3.1 走廊宽度（实测后的调参）🧭

初版把 RACE 图的路面按"悬崖边窄道"来设计（半宽 5~11 m），
结果冒烟测试里 **94% 的死亡都是"坠落深渊"**——高速滚木根本来不及修正，
整局变成比谁少掉下去。现在统一放宽：

```
构建期统一处理：node.halfWidth *= 1.4    node.shoulder += 2.5
```

即所有 RACE 图的路面与路肩一起放大，容错从 ±5 m 提到 ±10 m 左右。
宽窄的差异仍然保留（窄桥依旧无路肩），但"下坡加速"和"掉下去"之间有了余地。
调参前后对比见 `docs/06-DECISIONS.md` D26 / D27。

| 常量 | 值 |
|---|---|
| g（重力） | 16 m/s² |
| accel（输入加速度） | 22 m/s² |
| 平地速度上限 | 9 m/s |
| 下坡速度上限 | 22 m/s |
| 跳跃初速 vy | 5.4 m/s |
| 落地缓冲 | 落地 vy 超过 12 时，超出部分 ×0.6 转化为伤害（坠落伤害） |

### 2.4 下坡加速（核心爽点）🔒

用户口述"如果遇到下坡路则可以快速滚动"。实现为：

```
slopeGain = clamp(-∇h · moveDir, 0, 1.6)     // 只算顺着方向的下坡
maxSpeed  = 9 + 13 * clamp(slopeGain / 1.6, 0, 1)     // 最高 22 m/s
```

要点：
- **只有顺着下坡滚才提速**。横切下坡（横着滚下去）不提速——这样地图设计才有"选线"的意义。
- 达到 22 m/s 及以上时进入 **狂暴状态（BLITZ）**：视觉上滚木冒火/拖尾，撞击伤害 ×1.3，转向灵敏度 −40%（快到自己控不住）。

### 2.5 跳跃

- 仅在地面时可用（地面检测：贴地余量 `0.06`，且**上升中（`vy > 0`）绝不贴地**）。
- 初速 `JUMP_VELOCITY = 5.4 m/s`，重力 `16 m/s²` → **腾空 0.91 m、滞空 0.68 s**。
- 跳跃**保留全部水平速度**，且空中不受地形摩擦 → 跳跃可以用来抄近路、越沟、跳过机关。
- **不能二段跳**：空中再按无效，而且按下也**会被消费掉**，不会攒到落地那一刻生效。
- 空中可微调方向，但推力只有地面的 25%。
- 落地时若 `vy < -12` → 坠落伤害 `(|vy| - 12) * 4`。

### 2.6 加速（`Shift` / 触屏「加速」）🔒

| 项 | 值 |
|---|---|
| 按键 | 键盘 `Shift`（左右都认）· 触屏右下「加速」 |
| 效果 | **移速 ×1.5**（+50%） |
| 持续 | **3 s** |
| 冷却 | **15 s**（从按下那一刻起算） |

三个实现要点：

1. **作用点是速度上限与加速度，不是一次瞬时冲量。**
   `Roll.speedMultiplier()` 里乘 1.5，于是"加速"是这一段时间内真的更快，而不是弹一下。
   实测平地峰值速度 9.00 → 13.50 m/s，比值正好 1.500。
2. **冷却期间按了不生效，而且按键会被消费掉**（同跳跃，见 D43）——
   不会攒到冷却结束那一刻自动放出来。
3. **重生只清"正在生效的加速"，不清冷却**。冷却是资源不是状态，
   否则死一次就白赚一次加速（与 `ultimateCd` 的处理一致）。

AI 也会用它：冷却一好、跑起来了、前方 12 米内没有伤害机关就用掉，不留着。

### 2.7 普通攻击（`J` / 触屏「攻击」）🔒 —— **只在决赛关**

**这是前四关不存在的按键。**

| 项 | 值 |
|---|---|
| 按键 | 键盘 `J` · 触屏右侧按钮列最上格「攻击」 |
| 可用关卡 | **只有第 5 关（决战）**，`GameConfig.ATTACK_MIN_LEVEL = 5` |
| 形状 | 以人物朝向为中线的扇形：半径 **5.0 m**、总张角 **70°**（半角 35°） |
| 伤害 | **15**（普通伤害，吃刀盾/破防/蛋挞等增减伤；不是真伤） |
| 击退 | 8 m/s（径向），吃被击方的 `knockbackMultiplier()` |
| 冷却 | **5 s**，从挥出的那一刻起算 |
| 高度容差 | 2.5 m —— 隔着断崖上下两层打不到 |

四条实现要点：

1. **朝向取 `ItemSystem.forwardX/Z`**：移动中用速度方向，静止时用长轴垂线。
   与 AI 的寻敌、道具的"前方最近敌人"完全同一套口径。
2. **判定是可断言的纯函数** `AttackSystem.inCone(dx, dz, dy, fx, fz)`：
   正前方命中、背后不命中、超出 35° 不命中、超出 5 m 不命中、落差过大不命中。
   `tools/AttackTest` 逐条断言；AI 也用它（`hasTargetInCone`），
   所以不会出现"AI 隔着 8 米能打到我、我 5 米打不到它"。
3. **不检查隐身**：这是一次实打实的挥击，不是锁定 —— 否则隐身就成了绝对无解的贴脸手段。
   挥击命中同样会解除自己的隐身（与 D16 一致；攻击方还有一次 1.8 倍的破隐一击）。
4. **挥空也吃冷却**：否则空挥零成本，按住就能刷。

为什么只在决赛关：前四关要么在赛道上各跑各的、要么靠地形分胜负，加一个 5 秒档的
近身攻击只会让手感变杂；而第 5 关是唯一"所有人挤在同一个场地里互撞"的关卡，
那里缺的正是一个**人人都有、随时能用**的输出手段。

## 3. 碰撞与伤害

### 3.1 碰撞体

每根滚木一个球：中心 `(x, y + r, z)`，半径 `r = 0.5`。地形用高度场（heightfield）直接采样，不做 mesh 碰撞。

### 3.2 滚木 vs 滚木

```
1. 位置修正：把两球按质量反比推开（穿透深度 × 0.8 逐帧消解，允许少量软接触）
2. 冲量：标准弹性碰撞，恢复系数 e = 0.35（偏"实心木头互撞"的手感）
3. 伤害判定（单向，见总纲 §4.1）
4. 事件派发：OnHit(attacker, victim, damage, speed)  → 道具/决战技的钩子
```

**禁止**在伤害判定里读"攻击方当前 HP"之类会引发顺序依赖的状态——同一帧内的遍历顺序不能影响结果。实体遍历顺序固定为 **ID 升序**。

### 3.3 滚木 vs 静态碰撞体（墙/护栏）

- OBB（轴对齐 + 绕 Y 旋转）列表，每个静态体带 `boxHalfExtents` + `yaw`。
- 求解：把球心投影进 OBB 局部空间 → 求最近点 → 沿法线推出 → 速度反射，法向恢复系数 0.25。
- 护栏外无地面 → 掉落出地图边界判为"碎掉"（按模式重生或淘汰）。

### 3.4 伤害来源汇总

| 来源 | 伤害 |
|---|---|
| 高速撞击（被动） | `clamp((vRel − 8) × 2.0, 0, 45)` |
| 撞击反伤 | 上述 × 0.15 |
| **普通攻击（决赛关）** | **15**（扇形 5 m / 70°） |
| 坠落 | `max(0, |vy| − 12) × 4` |
| 机关 | 逐机关配置，见 `02` §5 |
| 道具 | 见 `03` |
| 决战技 | 见 `04` |

### 3.5 无敌帧

碎掉重生后 2.0 s。无敌期间：
- 伤害判定跳过该实体（`invulnTimer > 0`）
- 仍参与物理推挤
- 渲染为 8 Hz 闪烁 + 半透明

## 4. 存档点与重生

```
checkpointIndex：每个玩家独立维护，初始 0（起点算第 0 个）
spawn(player)：
    idx = player.checkpointIndex
    pos = map.checkpoints[idx].pos + 随机抖动(半径 1.2m)
    hp  = 100;  v = 0;  invuln = 2.0s
```

存档点激活条件（每逻辑帧检查）：

```
dist2D(player, cp) < 2.5  且  |player.y - cp.y| < 3.0  且  cp.index > player.checkpointIndex
```

激活效果：`checkpointIndex = cp.index`，并立刻获得 1.5 s 的 +20% 速度增益。

**存档点必须放在"机关之后、下坡之前"** —— 否则重生点会把玩家丢进机关里。这是地图数据的硬性校验规则（构建期断言）。

## 5. 时长与超时

| 情况 | 处理 |
|---|---|
| 名额填满 | 立刻结束本关，剩余玩家按 `progress` 排序决定淘汰顺序 |
| 时限到 | 进入 10 s 结算缓冲：所有玩家速度锁定为 0，弹结算面板 |
| 双方同时到线 | 按客户端上报的同帧时间戳，再按玩家 ID 升序（确定性 tie-break） |
| SURVIVAL 死亡阈值达成 | 立刻结束本关 |
| 仅剩 1 人（L5） | 立刻结束，宣布冠军 |

## 6. 玩家与 AI

- 一局 30 根滚木。默认 **1 个真人（本地玩家）+ 29 个 AI**。
- AI 难度分 3 档（按关卡递增）：`EASY / NORMAL / HARD`，影响反应延迟、摇杆抖动、道具使用率、决战技命中率。
- AI 输入与世界输入走**完全同一套接口**（`RollInput`），只是产生来源不同。这保证 AI 不会作弊，也让后续接联机时服务端能直接接管。
